# Scheduling Agent roadmap

The target is a local scheduling assistant that turns a student's natural-language request into an explainable draft and commits it only after explicit approval. The full workflow covers a feasible slot, a genuine conflict or missing detail, a correction that preserves earlier constraints, review of the supporting preference records, and a confirmed change that survives restart.

The proposed long-term release adds a validated offline interpreter while keeping the same scheduling and approval behavior. A hardware-accelerated option is ready when repeated, device-level measurements support enabling it.

## Evaluation and release decisions

- Keep request meaning, preference eligibility, calendar feasibility and write authority visible as separate layers. Local inference can supply the same typed interpretation. The planner and SQLite transaction retain authority.
- Build 30 fresh scenario families with two phrasings each. Stratify by language, date and duration wording, conflict, preference version, event ambiguity and approval boundary. Preserve paired phrasings in the same partition. Two reviewers should check references independently before a release run.
- Preserve raw results and failed runs. Track action and field accuracy, missing or changed constraints, unnecessary clarification, both-phrasings-correct rate and write-state invariants. Compare on identical fixtures and report p50/p95 latency, peak memory and energy per request under a fixed power measurement protocol.
- Gate the accelerator option on measured quality and energy. A provisional target is at least 20% lower median incremental energy per successful request than CPU inference using the same model and at most a 3 percentage-point loss in task success. A suspected accelerator assignment requires measurement. Treat GPU measurements as a separate comparison.
- Keep a manual calendar and rule-based clarification available when the interpreter fails. The user chooses whether to enable a hosted provider. A local-only release must pass its end-to-end tests with outbound network disabled.
- Revisit external calendar sync only after the local pilot. A connector has its own authority and data handling decisions, an explicit preview, conflict handling and a reversible migration plan.

## November 26 baseline

- Hosted course arm: 39/40 on synthetic English inputs. The rule parser passed 25/40. Both preserved events before approval.
- Qwen 2.5 1.5B Instruct Q4_K_M ran on the Apple M5 Pro through the local llama.cpp server. Plain JSON passed 0/40 inputs, with 41 rejected interpreter outputs in 42 calls. The verified strict JSON Schema request improved that to 2/40 inputs and three output errors. The median interpreter time in that strict run was about 2.39 seconds. Both local trials preserved the event table before approval.
- The installed llama.cpp build ignored the direct schema form on a controlled test. The nested OpenAI-compatible schema form honored the same enum restriction. Raw trial records retain that unsuccessful interface attempt. In the enforced run, 24 responses still failed text grounding. Valid JSON alone was insufficient for scheduling.
- Keep the hosted prototype as the course release. The next local-model milestone is a smaller interpretation contract or a stronger model that preserves source spans on a separate development set. The local baseline does not establish Neural Engine placement, offline installed-app behavior or energy use. Promotion remains gated on fresh bilingual acceptance and device measurements.
