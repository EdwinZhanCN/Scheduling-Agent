# Architecture

This document records the system boundaries that currently exist in the repository. Operational procedures belong in `.agents/skills/`, decision rationale in `.agents/decisions/`, and unfinished, multi-phase work in `.agents/exec-plans/active/`.

## System context

The repository is currently a monolithic TanStack Start application scaffold. The target product is a single-user Scheduling Agent, but calendar, agent, database, and scheduling capabilities have not been implemented. The current runnable surface consists only of the minimal page generated by TanStack Start and the build tooling.

## Module ownership

| Module or path    | Responsibility                                             | Entry point                                     |
| ----------------- | ---------------------------------------------------------- | ----------------------------------------------- |
| `src/routes/`     | File routes, root document, and placeholder home page      | `src/routes/__root.tsx`, `src/routes/index.tsx` |
| `src/router.tsx`  | Create and register TanStack Router                        | `getRouter()`                                   |
| `src/lib/`        | Shared utilities independent of specific features          | `src/lib/utils.ts`                              |
| `src/styles.css`  | Tailwind, shadcn tokens, and global styles                 | Stylesheet link in `src/routes/__root.tsx`      |
| `components.json` | shadcn code generation and external registry configuration | shadcn CLI                                      |

## Dependency direction

Routes may currently depend on `src/lib/` and global styles. The generated `src/routeTree.gen.ts` depends on route files; other modules must not depend on its internal implementation.

When feature modules are introduced, browser components may only call TanStack Start's server boundary. They must not directly import `better-sqlite3`, Drizzle connections, or the pi Agent runtime. Database and agent modules may depend on pure domain types and deterministic scheduling modules; dependencies in the reverse direction are prohibited.

## Data and state ownership

There is currently no business data, SQLite file, or database schema. `src/routeTree.gen.ts` is derived by `pnpm generate-routes`. `pnpm-lock.yaml` is the authoritative dependency resolution lockfile, and `components.json` is the authoritative configuration for shadcn registries and aliases.

## External boundaries

The runtime currently has no configured external APIs, model providers, or persistence services. FullCalendar, pi Agent SDK, Drizzle, and better-sqlite3 exist only as installed dependencies. Any future model API keys must remain in server-side environment variables.

## Runtime entry paths

- Development server: `pnpm dev`
- Production build: `pnpm build`
- Production build preview: `pnpm preview`
- Route generation: `pnpm generate-routes`
- Full local verification: `pnpm verify`

## Verification boundaries

| Boundary                                     | Current guardrail                        |
| -------------------------------------------- | ---------------------------------------- |
| TypeScript and import boundaries             | `pnpm typecheck`, `pnpm lint`            |
| Route generation and SSR build               | `pnpm generate-routes`, `pnpm build`     |
| Formatting and harness documents             | `pnpm check`                             |
| Test runner wiring                           | `pnpm test`; currently allows zero tests |
| Changes across boundaries or to dependencies | `pnpm verify`                            |
